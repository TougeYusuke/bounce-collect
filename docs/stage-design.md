# ステージ量産の手順（リアが回す）

> 狙い（2026-07-25 れいあ指定）:
> 「最終目標としては、わたしはほんとに細かい調整のみで、基本はリアたちのみでステージを量産できるとうれしい」
>
> ⚠️ だから **れいあに遊ばせて合否を判定させない**。機械で判定して、合格したものだけ見せる。
> ⚠️ これは**れいあの手間を減らすための内部ツール**。汎用のステージ評価器を作るのが目的ではない。

## 形の決まり（守る・れいあ指定）

1. **ゲートは最大3段**。高さは **300 / 410 / 520**
   - ⚠️ これより上へ戻さないこと。R2でバケツをひっくり返すと画像が **y=192** まで下りてくるので、
     1段目が 200 より上だと**バケツと重なって見える**（2026-07-25 れいあが「違和感」と指摘した正体）
   - ⚠️ **これ以上は下げられない**（2026-07-25 実測・崖は20pxしかない）。`320/430/532` まで下げると
     type-04 が**詰まりっぱなしで終わらない**（盤面850・通し480秒・30,010点）
2. **ジャンプ台は最下段のゲートの1つ**として置く（最下段と同じ y に横並び・重ねない）
3. **ジャンプ台は1台だけ**
4. ゲートは**壁までいっぱい**に置く（x=0 と x=360 に接する）
   - ⚠️ 8px 空けていた頃は、壁に貼り付いて落ちる玉がゲートの端を素通りしていた
     （既定ステージは右端に落とすと**4点**で終わっていた）
5. 仕切りの上端は **250 より下**、下端は **515 より上**（バケツにも漏斗にも食い込ませない）

これらは `tests/stages.test.ts` が見張っている（`npm test` で落ちる）。

## 🔴 仕切りの前提（2026-07-26 れいあ指定）

れいあ実言:
> - **仕切りとゲートは極力重ならないようにしてほしい**（隙間ができるなら多少は許容）
> - **球が落下できなくなるようなポケットはNG**（終わった後の待ち時間が長くなるから）
> - **仕切りと仕切りの間には必ずボールが入る隙間を開けること**（ただし斜めの仕切りなどの意図的な結合については許容）

実測（2026-07-26・全型を機械で数えた）:

```
交差なし  default / type-01 / type-05 / type-06 / type-07 / type-08
交差あり  type-02(2か所) / type-03(4か所) / type-04(3か所)
```

🔑 **れいあが手で作った type-01 は交差0。ツールが作った型ほど交差している**＝これはツール側の弱点。

| 前提 | 対応 |
|---|---|
| 仕切りとゲートを重ねない | ✅ `stages:gen` は対応済み（**レーンの線を先に決めて、各段のゲートをその線で切る**・線から8px離す）。⚠️ レーンを壁ぎわに置くと外側の破片が細すぎて捨てられ**その段が壁に届かなくなる**ので、壁から40px以上離す |
| ポケットNG | ✅ 形からでなく**結果で測る**＝`RUBRIC.LEFT_MAX`（終了時に盤面に残った玉）。⚠️ **実測では正常な12型すべてが0個**だったので線は厳しく引ける（いま4個）。落とす位置によっては素通りするので**平均でなく最大**を見る |
| 仕切り間にボールが入る隙間 | ✅ レーン幅は80か120（玉の直径16pxの5倍以上）。1レーンにつき仕切り2本だけなのでそれ以上狭まらない |

⚠️ **`stages:lane` は未対応**（仕切りを足すだけでゲートを切らない）。回すと交差した型ができる。

## 合格条件（`tools/stageRubric.ts` が正本）

落とす位置5か所 × 倍率の抽選2回 を実際に通しで回して測る。

| 条件 | 値 | なぜ |
|---|---|---|
| 当たりの位置のスコア | 1000〜**4300** | 低いと増える気持ちよさが出ない／高いとR2の配り切りが長い（⚠️ 2600 → 3200 → 4300 と2回上げている。玉が増える変更を入れるたびに現実に合わなくなるため） |
| 当たりの位置の通し時間 | 30〜95秒 | 短すぎ＝物足りない／長すぎ＝だれる |
| 最高 ÷ 最低 | **2.0倍以上** | 🔑 「適当に落とすとスコアが悪くなる」の担保（れいあ設計指定） |
| 500点以上の場所 | 3か所以上 | 少ないと運ゲーになる |

## 🔑 詰まった山が盛り返す（2026-07-25 れいあ要望）

れいあ実言:「元のゲームみたいに**球が詰まった状態でゲートを通ってモリモリって上に盛り返していく**動きが
見てて面白いから、このゲームでもそういう体験をできるようにしたい」

これを止めていたのは**混雑チェック**だった（実測: 増殖の85〜90%が「混んでいる」で捨てられていた＝
**詰まった時こそ増えない**作りになっていた）。ツマミは2つ:

| ツマミ | 何をする |
|---|---|
| `GATE_SPAWN_CLEARANCE` | 生まれる玉を置く時の最小距離。**いま 0.5**。⚠️ **0.5 を下回らない**（0.45で通し480秒の暴走を実測） |
| `MAX_PUSH_UPS` | 押し上げられてゲートを上へ抜けた玉が、そのゲートをもう一度使える回数。⚠️ **子へ継承**するので系譜ごとに必ず止まる |

実測（間隔／盤面ピーク／通し／スコア・4型の幅）:
`0.85 → 420〜535 / 55〜78秒 / 1,437〜1,779`（詰まる前に止まる＝物足りない状態）
`0.55 → 525〜850 / 58〜97秒 / 1,616〜4,589`
`0.50 → **採用**（2026-07-26 れいあが実機で3案から選択・満杯率8% → 26%・通し1分50秒 → 2分15秒）`
`0.45 → 850 / 95〜480秒 / 3,476〜38,963`（暴走）

## 🔑 「盛り上がり」は密度ではなく**隆起**（2026-07-26 判明）

れいあが見たいのは「**玉が増えた瞬間に山がボコッと持ち上がる動き**」。
⚠️ **密度を上げても解決しない**（そう解釈して3回外した）。しかも**物理では作れない**ことを実測で確認済み
（4通り・玉の重なりを位置で押し戻す方式は力が遠くまで伝わらない）。
→ **描画上だけ持ち上げる**（`src/render/heave.ts`）。⚠️ 物理は1ミリも変わらないので、
   ここを触ってもステージの採点はやり直しにならない。

## 🔑 「狙う意味」の作り方（実測で分かったこと）

**ジャンプ台を壁にぴったり寄せる。中央に置くと必ず「どこに落としても同じ」になる。**

理由: V字の漏斗が全ステージ共通で、どこに落ちた玉も最後は中央へ集まる。
中央に置いた台はその玉を結局全部拾ってしまう。壁に寄せると**反対側が本当に台の無い側**になり、
そこへ落とした玉は一度も跳ねずに流れる＝伸びない。

実測（2026-07-25・7型で総当たり）: 台を壁に寄せた型は合格、中央寄せの型は**全部 1.1倍**（＝差が出ない）。

⚠️ **ジャンプ台の「幅」では差はつかない**。狭めても中央にあると拾ってしまう（03/06/08で試して1.0〜1.1倍のまま）。

補助として、仕切りで囲った細い道（レーン）を台の無い側に作ると差が広がる。
type-01 は `x=260`（y250〜512）と `x=175`（y435〜510）でそれを作っている。

## 回し方

```bash
# いまある型を全部採点する（5分ほど）
npm run stages:check      # → stage-report.txt

# ゼロから作る（種40個で30分ほど）→ 合格したものだけ src/stages/ に保存
npm run stages:gen        # → stage-gen.txt
STAGE_GEN_SEEDS=100 STAGE_GEN_KEEP=6 npm run stages:gen   # 広く探す
STAGE_GEN_DRY=1 npm run stages:gen                        # 保存せず結果だけ見る

# 既にある型を直す（1型10分ほど）
npm run stages:lane       # → stage-lane.txt

# 形の決まりだけ確かめる（速い）
npm test
```

⚠️ **玉が増える変更を入れると1通しが重くなる**（2026-07-26 に間隔0.5へ変えて、1通し2秒 → 10秒になった）。
   種の数をそのままにすると時間が5倍になるので、`STAGE_GEN_SEEDS` を先に見積もること。

## 🔴 型を足したら解放テーブルにも足す（忘れるとテストが落ちる）

`tests/workshop.test.ts` が **「全部解放した時の型の数 == `STAGES` の数」** を見張っている。
`src/stages/` に型を保存しただけだと**数が合わずに落ちる**（2026-07-26 の既定ステージ二重登録もこれで見つかった）。

`src/core/workshop.ts` の `UNLOCKS` に1行足す。⚠️ **末尾に足さない**＝
型だけ遠くに固まって「遊んでも新しい盤面が出てこない」状態になる。既存の解放の**間に挿し込む**
（cost は前後の中間くらい）。⚠️ 工房の画面には型を出していないので、れいあ側の見え方は
「遊ぶほど黙って盤面の種類が増える」だけ。

⚠️ `tools/` は普段のテストにもCIにも入れない（`vitest.tools.config.ts` で分けてある）。
1回に何十回もゲームを通しで回すので、デプロイに混ぜると詰まる。

⚠️ **`stages:lane` を同じ型に2回かけない**。仕切りが二重に増え、最下段のゲートが削られ続ける。
1型だけやり直す時は先に素の状態へ戻すこと:

```bash
git checkout -- src/stages/type-04-tall-post.json     # 直前のコミットへ戻す
STAGE_LANE_ONLY=type-04-tall-post npm run stages:lane  # 1型だけ回す
```
